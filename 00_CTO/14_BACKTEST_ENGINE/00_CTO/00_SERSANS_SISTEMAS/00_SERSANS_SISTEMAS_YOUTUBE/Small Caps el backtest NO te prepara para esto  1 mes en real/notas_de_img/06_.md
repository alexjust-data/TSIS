# 7. Riesgos que deberíamos evitar al clonar el patrón

No copiaría literalmente un editor genérico sin protección.

Para TSIS la configuración debería tener tres capas:

```text
1. Sintaxis
2. Esquema
3. Semántica
```

Ejemplo:

```text
Sintaxis:
el archivo parsea

Esquema:
el campo existe y es numérico

Semántica:
heartbeat > 0
timeout_lectura < heartbeat
reintento_maximo >= reintento_inicial
```

También exigiría:

```text
config_version
effective_from
modified_at
modified_by
change_reason
checksum
previous_version
environment
```

# 8. Diseño recomendado para TSIS

No editaría directamente archivos activos.

Usaría este flujo:

```text
GUI
↓
Config Draft
↓
Syntax Validation
↓
Schema Validation
↓
Semantic Validation
↓
Diff Preview
↓
Approval
↓
Immutable Version
↓
Activation
↓
Runtime Reload
```

Y mantendría separados:

```text
config/
├── research/
├── backtest/
├── replay/
├── shadow/
└── live/
```

No permitiría que una configuración de backtest termine accidentalmente en live.
