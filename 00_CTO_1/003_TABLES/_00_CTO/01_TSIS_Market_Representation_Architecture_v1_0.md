# TSIS Knowledge Ontology

## Purpose

This page defines the ontology of TSIS.

It does **not** define datasets, schemas, features, strategies or
models.

It defines **what kinds of objects are allowed to exist** inside TSIS
and the legal relationships between them.

Every future contract, schema, registry and builder must be compatible
with this ontology.

------------------------------------------------------------------------

## Reality

Reality is the market itself.

Reality is never stored.

Reality can only be sampled.

Examples:

-   Orders submitted by market participants
-   Executions
-   Quotes
-   Corporate actions
-   News
-   Halts

------------------------------------------------------------------------

## Observation

An observation is a direct measurement of reality provided by a data
source.

Examples:

-   One trade
-   One quote update
-   One filing
-   One news publication

Observations are immutable.

------------------------------------------------------------------------

## Observable

An observable is a semantically identified observation.

Examples:

-   Trade Event
-   Quote Event
-   Halt Event
-   Filing Event

Observables preserve chronology and semantics but do not yet represent
mathematical knowledge.

------------------------------------------------------------------------

## Primitive

A primitive is the canonical representation of an observable.

Primitives are normalized.

Examples:

-   Trade primitive
-   Quote primitive
-   One-minute bar
-   Daily bar

Primitives are the lowest mathematical objects inside TSIS.

------------------------------------------------------------------------

## Feature

A feature is a deterministic mathematical function applied to
primitives.

Examples:

-   Trade count rate
-   Spread
-   Microprice
-   OFI
-   ATR
-   Gap %

A feature represents a property of the market.

A feature is never:

-   a strategy
-   a prediction
-   an action
-   a reward

------------------------------------------------------------------------

## Representation

A representation is an organized collection of features describing one
aspect of the market.

Examples:

-   Microstructure representation
-   Intraday representation
-   Daily representation
-   Fundamental representation

Representations are domain-specific.

------------------------------------------------------------------------

## State

A state is the complete observable representation of the market
available at one decision timestamp.

Properties:

-   Time legal
-   Point-in-time
-   Free of future information
-   Built only from observable representations

States never contain:

-   actions
-   rewards
-   outcomes
-   labels

------------------------------------------------------------------------

## Decision

A decision is generated by a policy.

Examples:

-   Buy
-   Sell
-   Hold
-   Do nothing

Decisions are consumers of states.

They are never inputs to state construction.

------------------------------------------------------------------------

## Outcome

An outcome describes what happened after a decision timestamp.

Examples:

-   Future return
-   MFE
-   MAE
-   Breakout success
-   Halt
-   Realized spread

Outcomes are evaluation objects.

They are never observable at decision time.

------------------------------------------------------------------------

# Legal derivation graph

``` text
Reality
    ↓
Observation
    ↓
Observable
    ↓
Primitive
    ↓
Feature
    ↓
Representation
    ↓
State
    ↓
Decision
    ↓
Outcome
```

Allowed derivations:

``` text
Observation → Primitive

Primitive → Feature

Feature → Representation

Representation → State

State → Decision

Decision → Outcome
```

Forbidden derivations:

``` text
Outcome → State

Outcome → Feature

Decision → Feature

Decision → State

Reward → Feature

Future → State
```

------------------------------------------------------------------------

# Fundamental principles

1.  Observability before prediction.

2.  Representation before strategy.

3.  States describe markets, not opinions.

4.  Features describe properties, not actions.

5.  Outcomes evaluate decisions but never construct states.

6.  Every derived object must preserve temporal legality.

# Chapter 1 --- Purpose

## Mission

TSIS is not designed to discover trading rules.

TSIS is designed to construct the most faithful mathematical
representation of the observable market possible.

Strategies, machine learning, reinforcement learning and optimization
are downstream consumers of this representation.

The objective of TSIS is therefore:

> To transform heterogeneous market observations into coherent,
> reproducible, temporally valid knowledge representations.

The architecture deliberately separates:

-   observations,
-   primitives,
-   features,
-   representations,
-   states,
-   decisions,
-   outcomes,

because each belongs to a different epistemological level.

Mixing those levels introduces ambiguity, leakage and non-reproducible
research.

Every future dataset, feature family, state builder, strategy engine and
learning algorithm must preserve this separation.

This document is the constitutional foundation of the TSIS
representation system.
