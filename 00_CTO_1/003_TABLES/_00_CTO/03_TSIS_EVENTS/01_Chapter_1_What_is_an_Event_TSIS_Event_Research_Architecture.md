# TSIS Event Research Architecture

## Chapter 1 --- What is an Event?

Version: 1.0 (Draft)

------------------------------------------------------------------------

# 1. Purpose

This chapter establishes the constitutional definition of an **Event**
inside TSIS.

An Event is one of the most overloaded words in quantitative finance. It
may refer to:

-   a market data message,
-   a news announcement,
-   a trading setup,
-   a chart pattern,
-   a research anchor,
-   an execution trigger.

TSIS deliberately separates these concepts.

The objective of this chapter is to define exactly what an Event is,
what it is not, and how it relates to representations, states and
scientific research.

------------------------------------------------------------------------

# 2. Fundamental Principle

An Event is **not** a trading opportunity.

An Event is **not** a prediction.

An Event is **not** a strategy.

An Event is an **observable occurrence** that is sufficiently
well-defined to serve as an anchor for scientific investigation.

------------------------------------------------------------------------

# 3. Why Events Exist

Representations answer:

> What is observable now?

Events answer:

> Around which observable occurrence should we organize research?

Without events there is no principled way to define:

-   research populations,
-   event windows,
-   control windows,
-   comparable states,
-   outcome horizons.

Events are therefore **research anchors**, not trading signals.

------------------------------------------------------------------------

# 4. Event Ontology

``` text
Reality

    ↓

```

An Event belongs to the Research Architecture, not to the Representation
Architecture.

------------------------------------------------------------------------

# 5. Formal Definition

A TSIS Event is:

> A uniquely identifiable, timestamped and reproducible occurrence
> defined by explicit eligibility rules and intended to anchor
> scientific observation.

Every Event must satisfy:

-   unique identity,
-   deterministic construction,
-   explicit timestamp,
-   explicit population,
-   reproducibility,
-   temporal legality.

------------------------------------------------------------------------

# 6. Event Categories

## 6.1 Raw Market Events

Direct observations.

Examples:

``` text
Trade
Quote Update
News Publication
SEC Filing
Trading Halt
Corporate Action
```

These originate directly from market data.

------------------------------------------------------------------------

## 6.2 Source Events

Domain-level events derived from one or more observations.

Examples:

``` text
Halt Resume
Scanner Qualification
Opening Auction Complete
Premarket Session Start
```

They define meaningful research anchors.

------------------------------------------------------------------------

## 6.3 Candidate Events

Events generated by deterministic detection rules.

Examples:

``` text
Breakout Candidate
VWAP Reclaim Candidate
Red-to-Green Candidate
Liquidity Vacuum Candidate
```

Candidate means:

> The market satisfied a predefined observable geometry.

It does **not** imply profitability.

------------------------------------------------------------------------

## 6.4 Research Events

Events promoted for scientific investigation.

A Research Event always possesses:

-   declared population,
-   event windows,
-   control populations,
-   outcome protocol.

------------------------------------------------------------------------

# 7. Event Identity

Every Event shall expose:

``` text
event_id
event_family
event_type
anchor_timestamp
instrument_id
population_id
eligibility_policy
builder_version
```

Identity is immutable.

------------------------------------------------------------------------

# 8. Event versus State

A State answers:

> What was observable?

An Event answers:

> Around what observable occurrence are we studying those states?

States describe.

Events organize research.

------------------------------------------------------------------------

# 9. Event versus Strategy

Example:

``` text
Event:
VWAP Reclaim Candidate
```

Possible downstream strategies:

``` text
Immediate Breakout
First Pullback
Fade Failure
Execution Timing
```

One Event may support many strategies.

Therefore Events remain strategy-independent.

------------------------------------------------------------------------

# 10. Event Windows

An Event never exists alone.

Every promoted Event owns one or more governed Event Windows.

Examples:

``` text
Pre-Event
Anchor
Immediate Response
Extended Response
Control Window
```

Windows determine which States belong to the investigation.

------------------------------------------------------------------------

# 11. Event Populations

Events are meaningful only as populations.

Example:

``` text
All Halt Resume Events

All Scanner Qualification Events

All Breakout Candidate Events
```

Scientific claims are made about populations, not isolated examples.

------------------------------------------------------------------------

# 12. Constitutional Rule

Inside TSIS an Event is a **research anchor**.

It is neither a signal nor a strategy.

Its purpose is to organize reproducible scientific observation around
explicitly governed occurrences in the market.

Every future Event family shall comply with this definition.
