# TSIS Event Research Architecture

## Chapter 2 --- Event Taxonomy

Version: 1.0 (Draft)

------------------------------------------------------------------------

# 2. Purpose

An Event cannot become a scientific object unless it belongs to a
well-defined taxonomy.

This chapter establishes the canonical classification system for every
Event inside TSIS.

A taxonomy prevents ambiguity, enables reproducible research populations
and allows different event families to coexist under one unified
architecture.

------------------------------------------------------------------------

# 2. Fundamental Principle

Every Event shall belong to exactly one primary Event Family.

Subtypes may exist, but semantic ownership is unique.

Taxonomy defines meaning.

Implementation defines detection.

------------------------------------------------------------------------

# 3. Taxonomic hierarchy

``` text
Event
    ↓
Event Family
    ↓
Event Type
    ↓
Event Variant
```

Example:

``` text
Event Family:
Scanner

Event Type:
Scanner Qualification

Variant:
RVOL > 10
```

------------------------------------------------------------------------

# 4. Canonical Event Families

## 4.1 Market Data Events

Directly observable.

Examples:

``` text
Trade
Quote Update
Bar Close
```

------------------------------------------------------------------------

## 4.2 Market Structure Events

Exchange or market status changes.

Examples:

``` text
Market Open
Market Close
Trading Halt
Resume
SSR Activation
```

------------------------------------------------------------------------

## 4.3 Information Events

Externally published information.

Examples:

``` text
News
SEC Filing
Corporate Action
Earnings
```

------------------------------------------------------------------------

## 4.4 Scanner Events

Generated by governed screening logic.

Examples:

``` text
Scanner Qualification
Scanner Removal
Scanner Rank Change
```

------------------------------------------------------------------------

## 4.5 Geometry Events

Generated from observable market geometry.

Examples:

``` text
Breakout Candidate
VWAP Reclaim Candidate
Opening Range Candidate
Red-to-Green Candidate
```

------------------------------------------------------------------------

## 4.6 Microstructure Events

Generated from trade/quote behaviour.

Examples:

``` text
Trade Burst
Quote Burst
Spread Collapse
Liquidity Vacuum Candidate
OFI Flip
```

------------------------------------------------------------------------

## 4.7 Research Events

Events promoted specifically for scientific investigation.

Examples:

``` text
Matched Control Window
Replication Population
Validation Sample
```

------------------------------------------------------------------------

# 5. Event Family Rules

Every family shall define:

``` text
family_name
semantic_definition
eligibility_policy
anchor_definition
window_policy
population_policy
```

------------------------------------------------------------------------

# 6. Event Type

Types refine one family without changing its meaning.

Example:

``` text
Family:
Trading Halt

Types:
LUDP
News Pending
Volatility Pause
Regulatory
```

------------------------------------------------------------------------

# 7. Event Variant

Variants specialize implementation.

Example:

``` text
Breakout Candidate

Variant A:
1m confirmation

Variant B:
5s confirmation

Variant C:
Microstructure confirmation
```

Variants remain members of the same Event Type.

------------------------------------------------------------------------

# 8. Event Identity

Every event taxonomy entry shall expose:

``` text
event_family
event_type
event_variant
canonical_name
description
version
```

------------------------------------------------------------------------

# 9. Forbidden Taxonomy

The following are not Event Families:

``` text
Winning Trade
Profitable Setup
Good Entry
High Probability Long
```

These are strategy concepts, not observable event classes.

------------------------------------------------------------------------

# 10. Constitutional Rule

The Event Taxonomy is the official semantic classification of all
research anchors inside TSIS.

Every Event must belong to one and only one primary family before it may
participate in Event Windows, Event States or Phenomenon Discovery.
