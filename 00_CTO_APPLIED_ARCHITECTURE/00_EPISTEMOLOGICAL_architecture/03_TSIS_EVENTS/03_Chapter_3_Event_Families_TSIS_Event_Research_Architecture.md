# TSIS Event Research Architecture

## Chapter 3 --- Event Families

Version: 1.0 (Draft)

------------------------------------------------------------------------

# 3. Purpose

An Event Taxonomy classifies events.

Event Families define the scientific meaning, boundaries and
responsibilities of each event category.

This chapter establishes the canonical Event Families recognized by TSIS
and the rules governing their evolution.

------------------------------------------------------------------------

# 3.1 Fundamental Principle

An Event Family groups events that represent the same observable market
phenomenon source.

An Event Family does **not** group strategies.

It groups research anchors.

------------------------------------------------------------------------

# 3.2 Family Responsibilities

Each Event Family shall define:

-   semantic meaning,
-   observable origin,
-   anchor definition,
-   eligibility policy,
-   population policy,
-   window policy,
-   outcome policy.

No Event Family may remain semantically ambiguous.

------------------------------------------------------------------------

# 3.3 Canonical Families

## Market Data

Observable directly from market messages.

Examples:

``` text
Trade
Quote Update
Bar Close
```

------------------------------------------------------------------------

## Market Structure

Changes in exchange or market state.

Examples:

``` text
Market Open
Market Close
Trading Halt
Resume
SSR Activation
```

------------------------------------------------------------------------

## Information

Externally published information.

Examples:

``` text
News
SEC Filing
Corporate Action
Earnings
```

------------------------------------------------------------------------

## Scanner

Events generated by governed scanning systems.

Examples:

``` text
Scanner Qualification
Scanner Removal
Rank Change
```

------------------------------------------------------------------------

## Geometry

Events describing observable price geometry.

Examples:

``` text
Breakout Candidate
VWAP Reclaim Candidate
Opening Range Candidate
Red-to-Green Candidate
```

------------------------------------------------------------------------

## Microstructure

Events derived from trades and quotes.

Examples:

``` text
Trade Burst
Quote Burst
Spread Collapse
Liquidity Vacuum Candidate
OFI Transition
```

------------------------------------------------------------------------

## Research

Research-specific anchor events.

Examples:

``` text
Matched Controls
Replication Samples
Validation Cohorts
```

------------------------------------------------------------------------

# 3.4 Family Independence

Families evolve independently.

Adding a new Geometry Event shall not redefine the semantics of
Microstructure or Scanner Events.

------------------------------------------------------------------------

# 3.5 Family Metadata

Every family shall declare:

``` text
family_name
description
observable_source
eligibility_policy
window_policy
population_policy
canonical_examples
version
```

------------------------------------------------------------------------

# 3.6 Promotion

A new Event Family becomes canonical only after:

-   semantic definition,
-   governance review,
-   validator implementation,
-   registry approval,
-   documentation.

Experimental families remain isolated until promotion.

------------------------------------------------------------------------

# 3.7 Forbidden Families

The following shall never become Event Families:

``` text
Winning Trades
Best Entries
High Probability Longs
Alpha Signals
```

These are strategy abstractions rather than observable market events.

------------------------------------------------------------------------

# 3.8 Constitutional Rule

Event Families constitute the canonical semantic organization of
research anchors inside TSIS.

Every Event belongs to exactly one primary Event Family, and every
scientific investigation shall explicitly declare the Event Family from
which its research population is derived.
