# TSIS Event Research Architecture

## Chapter 4 --- Event Populations

Version: 1.0 (Draft)

------------------------------------------------------------------------

# 4. Purpose

Scientific conclusions are never drawn from isolated Events.

They are drawn from **Event Populations**.

This chapter defines how TSIS constructs, governs and validates Event
Populations so that every research conclusion is reproducible,
statistically meaningful and scientifically auditable.

------------------------------------------------------------------------

# 4.1 Fundamental Principle

An individual Event is an observation.

An Event Population is the scientific unit of analysis.

``` text
Event
    ↓
Event Population
    ↓
Evidence
    ↓
Phenomenon
```

No canonical phenomenon shall be inferred from isolated events.

------------------------------------------------------------------------

# 4.2 Definition

An Event Population is a governed collection of Events satisfying a
common set of eligibility rules, semantic definitions and temporal
constraints.

The population is the object against which hypotheses are evaluated.

------------------------------------------------------------------------

# 4.3 Population versus Sample

TSIS distinguishes:

``` text
Population
```

The complete governed set of eligible Events.

and

``` text
Sample
```

A subset extracted from that population for a particular investigation.

Sampling never changes the population definition.

------------------------------------------------------------------------

# 4.4 Canonical Population Types

## Full Population

All Events satisfying the declared rules.

Example:

``` text
All Trading Halt Resume Events
2005–2026
```

------------------------------------------------------------------------

## Research Population

Events selected for one research question.

Example:

``` text
All VWAP Reclaim Candidates
with float < 20M
```

------------------------------------------------------------------------

## Candidate Population

Events generated by detection logic before scientific validation.

Example:

``` text
All Breakout Candidates
```

------------------------------------------------------------------------

## Validation Population

Independent population used to replicate findings.

It shall never overlap with the original research population unless
explicitly declared.

------------------------------------------------------------------------

## Control Population

Matched Events used to estimate baseline behaviour.

Examples:

``` text
Matched Time
Matched Liquidity
Matched Regime
Random Eligible Events
Near Misses
```

Control populations are mandatory whenever causal claims are
investigated.

------------------------------------------------------------------------

# 4.5 Population Eligibility

Every population shall define:

-   inclusion rules,
-   exclusion rules,
-   temporal scope,
-   market scope,
-   instrument scope,
-   data quality requirements.

Eligibility must be deterministic.

------------------------------------------------------------------------

# 4.6 Population Independence

Different Event Families produce different populations.

Examples:

``` text
Scanner Qualification Population

Trading Halt Population

Liquidity Vacuum Population
```

Scientific conclusions are population-specific.

Generalization requires separate validation.

------------------------------------------------------------------------

# 4.7 Population Metadata

Every population shall declare:

``` text
population_id
population_name
event_family
event_type
eligibility_policy
coverage_policy
time_range
instrument_scope
expected_size
builder_version
status
```

------------------------------------------------------------------------

# 4.8 Population Lineage

Every Event Population shall be traceable to:

``` text
Event Family
Detection Builder
Eligibility Contract
State Version
Feature Registry Version
Research Protocol
```

Population lineage guarantees reproducibility.

------------------------------------------------------------------------

# 4.9 Population Evolution

Population definitions may evolve only through explicit versioning.

Changing:

-   eligibility,
-   scope,
-   event definitions,
-   quality rules,

creates a new population version.

Historical populations remain immutable.

------------------------------------------------------------------------

# 4.10 Population Completeness

Every population shall state whether it claims:

``` text
FULL_POPULATION

PARTIAL_POPULATION

EXPERIMENTAL_POPULATION
```

The completeness claim must be verifiable.

------------------------------------------------------------------------

# 4.11 Constitutional Rule

Event Populations are the fundamental scientific unit of empirical
research inside TSIS.

Every hypothesis, validation protocol, phenomenon and knowledge object
shall reference explicitly defined Event Populations.

Scientific claims without governed populations are architecturally
invalid.
