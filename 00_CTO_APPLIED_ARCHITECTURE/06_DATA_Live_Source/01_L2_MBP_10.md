# Conclusión real

Para un usuario retail que quiere **5–6 small caps al día**, hoy no he encontrado una oferta pública que entregue simultáneamente:

```text
MBP-10 normalizado
event-by-event
timestamps del exchange
sequence numbers
order count por nivel
10 niveles completos
histórico con el mismo esquema
US equities multivenue
precio inferior a 200–300 USD/mes
```

**Databento sí cumple la calidad**, pero no el precio:

* Standard: 179 USD/mes, pero no desbloquea el live profundo relevante.
* Plus: **1.500 USD/mes**, contrato anual, con “enhanced live data”.
* Unlimited: 4.000 USD/mes.
* Además, Databento dice expresamente que el live usage-based **no está disponible para Databento US Equities**. Por tanto, no existe la estrategia de “compro sólo cinco tickers durante un día”. ([Databento][1])

Esto elimina a Databento como solución retail normal, salvo que negocien una excepción comercial no publicada.

# La mejor oportunidad real: TradeStation API

De todo lo revisado, **TradeStation es la única alternativa pública que se acerca de verdad a MBP-10 retail por API**, aunque tiene limitaciones importantes.

## Qué ofrece exactamente la API

El endpoint oficial es:

```text
Stream Market Depth Aggregates
```

Características documentadas:

* streaming HTTP;
* equities;
* una fila separada por precio y lado;
* datos agregados desde participantes;
* parámetro `maxlevels`;
* valor por defecto: 20 niveles;
* puedes solicitar 10 niveles.

Por ejemplo:

```http
GET /v3/marketdata/stream/marketdepthaggregates/HOLO?maxlevels=10
```

La documentación define el servicio como:

> profundidad agregada; una cotización separada por precio y lado, utilizando datos agregados de los participantes.

Por estructura, esto es mucho más cercano a **MBP por precio** que el Level 2 tradicional basado en filas de market makers. ([TradeStation API][2])

## Qué paquetes de datos necesitarías

Para un usuario non-professional:

### Opción Nasdaq únicamente

```text
Enhanced Market Depth       25 USD/mes
Nasdaq Package #3           17 USD/mes
---------------------------------------
Total                       42 USD/mes
```

Nasdaq Package #3 incluye:

* Level 1;
* Level 2;
* TotalView.

TotalView necesita Enhanced Market Depth. ([TradeStation][3])

### Nasdaq + ARCA + BATS/Direct Edge

```text
Enhanced Market Depth       25 USD
Nasdaq Package #3           17 USD
ARCA Book                    11 USD
BATS + Direct Edge Books     13 USD
NASDAQ BX TotalView           2 USD
-----------------------------------
Total aproximado             68 USD/mes
```

Esto es, comercialmente, muchísimo más cercano a lo que buscas que Databento. ([TradeStation][3])

## Por qué TradeStation puede ser la solución

Para tus 5–6 tickers seleccionados:

```text
scanner externo
      ↓
selección 5–6 acciones
      ↓
abrir 5–6 streams marketdepthaggregates
      ↓
maxlevels=10
      ↓
guardar cada mensaje
      ↓
mantener libro local
      ↓
generar features MBP-10
```

Coste de datos:

```text
42–68 USD/mes aproximadamente
```

No se cobra por ticker.

Puedes cambiar los símbolos cada día y reutilizar las conexiones.

# Pero todavía no puedo llamarlo “equivalente a Databento MBP-10”

TradeStation no publica con suficiente claridad varios campos fundamentales:

* timestamp originado por el exchange;
* timestamp de recepción;
* sequence number global o por símbolo;
* order count por nivel;
* identificador del venue después de la agregación;
* mensajes explícitos de reset/snapshot/end-of-snapshot;
* política de recuperación tras desconexión;
* si cada cambio del libro produce obligatoriamente un mensaje;
* límites exactos de streams concurrentes;
* velocidad máxima o throttling;
* precisión del timestamp;
* si la agregación es consolidada entre books o sólo agrupación de participantes disponibles.

Por tanto, TradeStation puede ser:

```text
MBP-like de 10 niveles
```

pero no está demostrado públicamente que sea:

```text
MBP-10 institucional normalizado y loss-detectable
```

## La diferencia es crítica para ML

Para trading visual, basta con ver:

```text
precio
tamaño
lado
nivel
```

Para ML serio necesitas saber si perdiste eventos.

Sin sequence numbers o controles de integridad, una desconexión puede producir:

```text
libro local incorrecto
→ imbalance incorrecto
→ feature incorrecta
→ label/modelo contaminado
```

Por eso TradeStation es el mejor candidato económico, pero necesita una prueba técnica antes de adoptarlo como fuente de verdad.

# Segunda opción: IBKR, pero no es MBP-10 científico

IBKR permite:

```python
reqMktDepth(
    tickerId,
    contract,
    numRows=10,
    isSmartDepth=True,
    mktDepthOptions=[]
)
```

y devuelve callbacks:

```text
updateMktDepth
updateMktDepthL2
```

con:

* posición;
* market maker;
* operación insert/update/delete;
* lado;
* precio;
* tamaño;
* smart depth.

IBKR afirma que market depth se envía sin muestreo ni filtrado, pero añade una advertencia decisiva:

> no garantiza que se muestre cada precio cotizado para un instrumento. ([Interactive Brokers][4])

Eso impide tratarlo como un feed institucional completo.

## Otra corrección importante sobre los límites

Mi respuesta anterior dijo incorrectamente que cada booster añadía una línea de depth.

La tabla oficial actual es:

| Líneas totales | Depth simultáneo |
| -------------: | ---------------: |
|            100 |                3 |
|            200 |                3 |
|            300 |                3 |
|            400 |                3 |
|            500 |                4 |
|            600 |                5 |
|            700 |                6 |

Por tanto, para obtener 6 símbolos L2 simultáneos necesitas aproximadamente:

```text
700 líneas totales
=
base 100
+
6 Quote Boosters
```

No tres boosters.

El coste sería:

```text
6 × 30 USD = 180 USD/mes
```

más las suscripciones de los exchanges. ([Interactive Brokers][5])

## Además, Nasdaq por API requiere más suscripciones

Para recibir Nasdaq TotalView o market depth fuera de TWS, IBKR exige:

1. L1 US equities;
2. Nasdaq TotalView-OpenView;
3. Nasdaq TotalView-OpenView EDS para uso off-platform/API.

Esto encarece y complica la solución. ([Interactive Brokers][5])

## Problemas para ML

IBKR no proporciona en estos callbacks:

* timestamp de exchange;
* sequence number;
* número de órdenes por precio;
* indicador fiable de gap;
* histórico depth;
* replay con el mismo esquema;
* garantía de libro completo.

Por tanto, IBKR puede servir para:

```text
prototipar features online
validar una estrategia discrecional
hacer inferencia experimental
```

Pero no lo elegiría como dataset científico principal para entrenar un modelo profundo de order book.

# Tercera opción: dxFeed directo

dxFeed sí dispone técnicamente de una arquitectura mucho más fuerte.

Su `Order` event y su modelo de order book soportan:

* snapshots;
* transacciones;
* reconstrucción del libro;
* fuentes múltiples;
* indexación de órdenes;
* OrderBookModel en Java;
* en Enhanced Order Book:

  * order ID;
  * action;
  * trade price;
  * lifecycle adicional.

dxFeed recomienda explícitamente reconstruir el libro con su `OrderBookModel`, que gestiona transacciones y snapshots. ([kb.dxfeed.com][6])

## El problema

La API y el modelo existen, pero no aparece un precio público de acceso programático retail para US equities.

El producto barato de dxFeed normalmente llega mediante:

```text
Bookmap + dxFeed
```

Eso da full depth para visualización, pero el hecho de que Bookmap pueda visualizarlo **no implica que el usuario tenga derecho a extraer el feed bruto desde una aplicación externa**.

La licencia de una plataforma visual y la licencia de una API non-display son productos distintos.

Por tanto:

```text
dxFeed directo = técnicamente válido
               = comercialmente no confirmado como retail barato
```

No puedo afirmar que sea una solución de 50–100 USD/mes sin una cotización expresa de dxFeed.

# Bookmap no es automáticamente una puerta trasera

Bookmap puede mostrar full depth de US equities con dxFeed. ([Bookmap][7])

Pero para TSIS habría que distinguir tres APIs diferentes:

1. API de add-ons de Bookmap.
2. API de trading/conectividad.
3. Acceso al flujo raw del proveedor.

Que Bookmap permita desarrollar add-ons no significa necesariamente que puedas:

```text
interceptar todos los eventos raw
guardar el libro completo
usar esos datos fuera de Bookmap
entrenar modelos externos
crear un dataset histórico permanente
```

Además, podrían aplicarse restricciones de:

* non-display use;
* derived data;
* almacenamiento;
* redistribución;
* uso automatizado.

Por eso no considero Bookmap una solución confirmada hasta revisar específicamente el SDK y los términos de dxFeed.

# Qué significa realmente “consolidado”

Aquí hay otro problema estructural.

Una small cap puede tener liquidez en:

```text
Nasdaq
NYSE Arca
Cboe BZX
Cboe EDGX
Nasdaq BX
IEX
NYSE National
otros
```

No existe un feed SIP con diez niveles consolidados.

El SIP proporciona principalmente el NBBO, no un consolidated MBP-10 nacional.

Para construir un MBP-10 consolidado tendrías que:

```text
Nasdaq TotalView
+ ARCA Book
+ BZX Book
+ EDGX Book
+ BX TotalView
+ otros venues
          ↓
sincronizar por timestamp/sequence
          ↓
agregar por precio
          ↓
calcular top 10 nacional
```

Eso es precisamente lo que encarece una solución como Databento.

## TradeStation parece ofrecer una agregación más práctica

Su endpoint dice que devuelve datos agregados de participantes. Pero no he encontrado una afirmación oficial suficientemente precisa que garantice:

```text
consolidación completa y sincronizada de todos los venues contratados
```

Puede que los paquetes adicionales incorporen más participantes al stream, pero eso debe comprobarse empíricamente.

# Cómo saber si TradeStation sirve científicamente

Antes de construir meses de datos, haría un benchmark de 10 sesiones.

## Test 1 — Completitud temporal

Registrar:

```text
mensajes por segundo
intervalos sin update
máximo gap entre eventos
distribución de latencia local
```

## Test 2 — Consistencia del libro

Comprobar:

```text
bid levels descendentes
ask levels ascendentes
best bid <= best ask
no tamaños negativos
no posiciones duplicadas
```

## Test 3 — Comparación con L1

Comparar continuamente:

```text
TradeStation best bid/ask
vs.
SIP NBBO
vs.
IBKR L1
```

Si el top level diverge con frecuencia, el libro no puede usarse sin modelar la fuente.

## Test 4 — Comparación puntual con Databento histórico

Puedes comprar **histórico pay-as-you-go** de las mismas acciones y fechas en Databento.

La restricción de 1.500 USD afecta al live profundo, no necesariamente a pequeñas descargas históricas usage-based. Databento permite histórico sin suscripción y por consumo. ([Databento][1])

Compararías:

```text
TradeStation live grabado
vs.
Databento histórico MBP-10/MBO
```

No serían necesariamente el mismo conjunto de venues, pero permitiría medir:

* dirección del imbalance;
* cambios de profundidad;
* frecuencia de updates;
* book slope;
* liquidity withdrawal;
* eventos de spread;
* poder predictivo de las features.

Esta combinación es mucho más inteligente que pagar 1.500 USD mensuales:

```text
TradeStation barato para capturar live
+
Databento histórico puntual para auditar
```

# El problema del entrenamiento

Para entrenar ML no basta con comprar live hoy.

Necesitas acumular suficientes ejemplos:

```text
5 tickers/día
× 250 días
= 1.250 ticker-sessions/año
```

Para small caps activas esto puede generar muchos millones de eventos.

Pero los datos estarán sesgados porque sólo capturas los tickers seleccionados por tu scanner.

Eso no es necesariamente malo, siempre que tu objetivo sea:

```text
P(outcome | ticker seleccionado por el scanner)
```

y no:

```text
P(outcome | universo completo)
```

De hecho, para TSIS es coherente capturar sólo los candidate events que realmente entran en tu universo operativo.
